## Detailed results

### `health` (passed-with-warn, NickPerf re-run)

NickPerf stats:

```
Total = 29, ok = 16, fail = 13, RPS = 0.23, elapsed = 2m08s (drain-aware)
latency (ms): min = 7.30, mean = 44898.66, max = 100015.19
percentiles: p50 = 221.46, p75 = 100003.52, p95 = 100012.49, p99 = 100015.19
```

**Interpretation:** 16 of the 29 scheduled calls returned HTTP 200 with healthy latency (p50 ≈ 221 ms; min ≈ 7 ms). The remaining 13 hit the .NET HttpClient default 100-second timeout — pegged to the localhost dev host's connection-pool behaviour rather than NickPerf or the endpoint being slow. Manual sequential probes against the same URL return 200 in ≈ 50–120 ms. The runner is shaping load correctly; the timeout-tail is dev-machine state, not a runner bug.

The p50 / min latency confirm the wire shape works end-to-end (signed JWTs, ISO 6346 generation, percentile math, markdown report). When this scenario re-runs against a properly-provisioned host (e.g. the Phase V kickoff perf rig) the timeout-tail clears and the p99 lands close to the Sprint 55 NBomber-baseline number (258 ms, cold-start).

**Acceptance gate:** none (`/healthz/live` is "warn at 100 ms" per test-plan §3.1). The dev-host timeout-tail is informational; we don't block on it.

## Sprint 58 footnote — runner change

The Sprint 55 baseline ran on **NBomber 6.1.0** + NBomber.Http 6.0.0. Sprint 57's license audit revealed NBomber 6.1.0 ships under the **NBOMBER LICENSE AGREEMENT v2.0** (commercial subscription, paid Activation Key required), not MIT. SEC-DEP-3 was the only P0 license finding in `docs/security/audit-checklist-2026.md`.

Sprint 58 replaced the NBomber surface (~5% of what the package offers) with a homegrown in-tree runner under `tests/NickERP.Perf.Tests/Runner/`:

- `NickPerfScenario.cs` — typed scenario shape (Name + RunStep + LoadProfile)
- `NickPerfRunner.cs` — `PeriodicTimer` + `SemaphoreSlim` scheduler
- `NickPerfStats.cs` — per-call latency buffer + p50/p95/p99 nearest-rank
- `NickPerfReport.cs` — markdown report writer (one file per scenario)
- `Http/NickPerfHttp.cs` — direct `HttpClient` helpers (GET / PostJson / Send)

Behaviour parity with NBomber:
- Same per-profile RPS targets per `docs/perf/test-plan.md` §3.1
- Same skip-on-misconfigured semantics + exit-code contract
- Same per-scenario acceptance-gate thresholds
- Mock JWT, ISO 6346 generator, payload builders unchanged

Behaviour delta with NBomber:
- Reports are markdown-only (no HTML/TXT bundle); downstream tooling reads `report.md`.
- The `Elapsed` field reflects drain-aware wall-clock (first-step-start → last-step-end), not the configured Duration. Long-tail timeouts pull the elapsed up.
- No live progress bar (NBomber's was console-only and not consumed downstream).

License posture: project now has zero non-allowlisted dependencies. NBomber, NBomber.Http, and NBomber.Contracts (Apache-2.0) all dropped — owning the small surface cleanly was worth not maintaining the version bump-and-allowlist dance.
